Deliverables

Motivation

During Phase 5 (Steps 12–14), both the API and Web projects maintained duplicate copies of the same domain models. This caused:

  • Ambiguous reference errors when the same class (e.g. DonorSummaryRow) existed in both projects
  • Drift risk — adding a property to one copy but forgetting the other
  • Unnecessary maintenance — every new model required two files

The fix: extract all shared POCOs into a BloodCenterOS.Core class library referenced by both API and Web.

Architecture Change

Before (duplicate models):
  BloodCenterOS.API/Models/*.cs   (14 models)
  BloodCenterOS.Web/Models/*.cs   (17 models)
  └── same classes, two copies, ambiguous references

What Was Fixed

  1. Created BloodCenterOS.Core — net9.0 class library, BloodCenterOS.Core.Models namespace, nullable enabled
  2. Moved 22 POCOs — all shared domain models from both API and Web into Core
  3. Added project references — both API and Web reference BloodCenterOS.Core
  4. Updated imports — ~63 .cs files across both projects changed using BloodCenterOS.*.Models → using BloodCenterOS.Core.Models
  5. Fixed ambiguous references — removed 7 duplicate DTOs from AdminDtos.cs (CenterConfigItem, SystemConfigItem, LookupTypeItem, LookupValueItem, DonorSummaryRow, InventorySummaryRow, CampSummaryRow)
  6. Restored StatusBadge — BloodTestRecord.StatusBadge computed property was lost during migration; added back as switch expression mapping OverallStatus → Bootstrap badge CSS class
  7. Updated _ViewImports — @using BloodCenterOS.Core.Models added so all Razor views resolve Core types globally
  8. Updated ViewModels — added using BloodCenterOS.Core.Models to CampViewModel, CollectionViewModel, ComponentViewModel, DonorViewModel, InventoryViewModel, TestViewModel
⚠ Cleanup check
Before this cleanup, dotnet build failed with dozens of ambiguous-reference and missing-type errors across both API and Web projects. After the Core extraction, all projects compile clean. No runtime behavior changed — this was purely a structural refactor.

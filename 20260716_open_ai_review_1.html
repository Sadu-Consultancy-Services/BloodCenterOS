Overview

BloodCenterOS is an open-source Blood Center Management System for India (NBTC/NACO compliant), developed by Sadu Consultancy Services (Pune, India). It is currently in Phase 1 (Analysis & Database Design).

Goal: Convert the existing SQL Server (T-SQL) schema to PostgreSQL and build the full application stack on .NET 9 with Dapper + Npgsql.

Assessment

Strengths

  • Schema is comprehensive — covers full blood center lifecycle (donor → collection → testing → components → inventory → issue → billing → reporting)
  • NBTC/NACO compliant design suitable for Indian regulatory reporting
  • Multi-center architecture built in (CenterId on most tables)
  • Clean "no FK" design optimized for SP-based high-performance transactions
  • Good audit trail (AuditLog, ChangeLog, LoginHistory)

Gaps & Observations

1. No stored procedures in the repo yet — only DDL. SPs are the core of the data access strategy.
2. No PostgreSQL version exists — full T-SQL → PL/pgSQL conversion needed.
3. Schema uses NVARCHAR(MAX) extensively — should right-size columns for PostgreSQL.
4. No cross-matching compatibility rules table (logic presumably in SPs).
5. Some tables have overlapping concerns (e.g., DonorDonationHistory overlaps with CollectionRecord).
6. No seed/master data scripts provided.

Recommended Step-by-Step Plan

  1. Convert v3.1 SQL Server → PostgreSQL Schema
    Map types (NVARCHAR → VARCHAR, DATETIME2 → TIMESTAMP, BIT → BOOLEAN, BIGINT IDENTITY → BIGSERIAL), add FK constraints, convert indexes, add created_at/updated_at conventions.
  2. Create PostgreSQL Stored Procedures (PL/pgSQL)
    Map the intended SP layer — CRUD per module, business logic, reporting queries.
  3. Add NuGet Packages
    Npgsql, Dapper, ClosedXML, QuestPDF, BCrypt.Net-Next (password hashing), Serilog (logging).
  4. Build Repository Layer
    Create IDonorRepository, ICollectionRepository, etc. using Dapper + Npgsql calling stored procedures.
  5. Build Domain Models
    POCO classes matching the 87 tables — could be auto-generated from the PostgreSQL schema.
  6. Implement Authentication & Authorization
    JWT-based or cookie auth with role-based access for Super Admin, Center Admin, MO, Technician, etc.
  7. Build Web Controllers & Views (Module by Module)
    Start with Donor Management → Collection → Testing → Components → Inventory → Issue → Billing → Reports.
  8. Implement Reporting Engine
    Excel exports via ClosedXML, PDF via QuestPDF for NACO/State compliance reports.
  9. Add Seed Data
    Blood groups, default roles/permissions, lookup values, Indian states/districts/cities.
  10. Testing & Deployment
    Unit tests, integration tests, Docker Compose for PostgreSQL + .NET app, CI/CD pipeline.
Priority Start: Step 1 (PostgreSQL schema conversion) followed by Step 2 (PL/pgSQL stored procedures) — these are the foundation everything else builds on.

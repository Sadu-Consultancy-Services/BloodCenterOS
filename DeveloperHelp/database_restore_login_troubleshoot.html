Database Restore & Login Troubleshooting

This guide covers the two most common issues reported by users:

  1. Cannot restore the PostgreSQL database — the dump files are in a binary format that requires pg_restore, not psql -f.
  2. Cannot login (invalid user id or password) — causes and step-by-step fixes, including verifying the seed user, checking the BCrypt hash, and resetting from the database.

Part 1 — Database Restore

The Problem

The database dump files in DB/ (e.g. bloodcenter_20260722_1.sql) appear to be .sql files, but they are actually pg_dump custom-format backups (binary format, header bytes PGDMP). If you run:

psql -U postgres -d bloodcenter -f bloodcenter_20260722_1.sql

you will see garbage/binary errors or "invalid command" because psql expects plain-text SQL, not the custom binary format.

The Fix — Use pg_restore

Both .sql and .backup files in DB/ are custom-format dumps. Use pg_restore to restore them:

Option A: Restore directly into a database (recommended)

pg_restore -U postgres -h localhost -p 5432 -d bloodcenter --clean --if-exists "DB\bloodcenter_20260722_1.sql"
  • --clean — drops existing objects before restoring (handy for re-import).
  • --if-exists — avoids errors if an object does not exist.
  • -d bloodcenter — target database name. The dump includes CREATE DATABASE so you can also use -C (create database) instead of -d.

Option B: Convert to plain SQL first (for inspection)

pg_restore -U postgres -f restore_output.sql "DB\bloodcenter_20260722_1.sql"

This produces a plain-text restore_output.sql that you can read or feed to psql -f:

psql -U postgres -d bloodcenter -f restore_output.sql

Option C: Using the .backup file

pg_restore -U postgres -h localhost -p 5432 -d bloodcenter --clean --if-exists "DB\bloodcenter_20260722_1.backup"

Prerequisites Check

  • PostgreSQL must be installed. BloodCenterOS targets PostgreSQL 18.x. Download from postgresql.org.
  • pg_restore must be on your PATH (it ships with PostgreSQL). Verify: pg_restore --version.
  • Create an empty database first if the dump doesn't include CREATE DATABASE:
createdb -U postgres bloodcenter

Alternative Approach — Individual SQL files (for devs)

If pg_restore is not available or you prefer running individual scripts, you can rebuild the database from source:

psql -U postgres -d bloodcenter -f "DB\OLD\BloodCenterOS_DB_v3.1_PostgreSQL.sql"
psql -U postgres -d bloodcenter -f "DB\OLD\seed_admin.sql"
psql -U postgres -d bloodcenter -f "DB\OLD\seed_reference_data.sql"
:: Then apply all fn_*.sql files in OLD/
for %f in (DB\OLD\fn_*.sql) do psql -U postgres -d bloodcenter -f "%f"

This builds the schema, seed data, and stored procedures from scratch.

Part 2 — Login Troubleshooting ("Invalid user id or password")

The Symptom

After restoring the database and starting the API, logging in with admin / admin@123 returns:

{ "success": false, "message": "Invalid credentials" }

Possible Causes

CauseWhyFix
1. Database restore failed The seed admin user never got inserted because the dump wasn't restored correctly (see Part 1). Verify pg_restore completed without errors. Check if the Users table has data:
2. No admin user in the table The Users table is empty or the admin account was not seeded.
psql -U postgres -d bloodcenter -c "SELECT UserId, Username, IsActive FROM Users;"

If empty, run the seed script:

psql -U postgres -d bloodcenter -f "DB\OLD\seed_admin.sql"
3. Wrong username or password The default credentials are case-sensitive. The username is admin (lowercase). The password is admin@123. Try typing the password manually (not copy-paste) to avoid hidden characters. Default credentials: admin / admin@123.
4. BCrypt hash version mismatch The seed SQL uses $2a$ BCrypt prefix, but BCrypt.Net on .NET 9 may expect $2b$. In most cases BCrypt.Net handles $2a$ fine, but there are edge cases with certain builds. Generate a fresh BCrypt hash for admin@123 and update the admin record:
psql -U postgres -d bloodcenter -c "UPDATE Users SET PasswordHash = '\$2b\$11\$EDuMXQ8JdPSZXOahB17Ln.rSagzAC54LhwFOhKQW1bguBo.DmzZ5i' WHERE Username = 'admin';"

Or generate a new hash using an online BCrypt tool and update with that.
5. Application not reading the correct database The API's appsettings.json might point to a different database (e.g. a test DB) or have wrong credentials. Check BloodCenterOS.API/appsettings.json: 
"ConnectionStrings": {
  "BloodCenterOS": "Host=localhost;Port=5432;Database=bloodcenter;Username=postgres;Password=postgres;..."
}

Ensure Database=bloodcenter points to the database you restored into.
6. User account is inactive The IsActive column on the Users table is false or 0.
psql -U postgres -d bloodcenter -c "UPDATE Users SET IsActive = TRUE WHERE Username = 'admin';"
7. API talking to HTTP (redirect drops auth) If the API uses UseHttpsRedirection and you call http://localhost:5000, the Bearer token is lost on the HTTPS redirect (documented in major_update_20260717_1.html). Access the API over https://localhost:5001 (HTTPS). The Web app should use Api:BaseUrl: https://localhost:5001.

Step-by-Step Login Recovery

  1. Verify the database connection. Make sure PostgreSQL is running and the API config points to the right database.
  2. Check if the admin user exists:
    psql -U postgres -d bloodcenter -c "SELECT UserId, Username, IsActive FROM Users WHERE Username = 'admin';"
    If no rows returned, seed the admin:
    psql -U postgres -d bloodcenter -f "DB\OLD\seed_admin.sql"
  3. Test the BCrypt password hash. Temporarily update the password with a known-good hash:
    psql -U postgres -d bloodcenter -c "UPDATE Users SET PasswordHash = '\$2a\$11\$EDuMXQ8JdPSZXOahB17Ln.rSagzAC54LhwFOhKQW1bguBo.DmzZ5i' WHERE Username = 'admin';"
  4. Make sure the user is active:
    psql -U postgres -d bloodcenter -c "UPDATE Users SET IsActive = TRUE WHERE Username = 'admin';"
  5. Restart the API and try logging in again with admin / admin@123.
  6. Still not working? Check the API logs for the specific error. Start the API and watch the console output during a login attempt — it will show the Npgsql or BCrypt exception.

Creating a New Admin User from Scratch (Last Resort)

If the seed script doesn't work or the BCrypt hash is problematic, drop into the psql shell and create a user with a freshly generated hash:

-- 1. Find a role id (e.g. Administrator = 1)
SELECT RoleId, RoleName FROM Roles;

-- 2. Find a center id
SELECT CenterId, CenterName FROM BranchMaster;

-- 3. Insert a new admin user
--    Replace '<bcrypt_hash>' with a hash of your chosen password
INSERT INTO Users (CenterId, Username, PasswordHash, PasswordSalt, Email, RoleId, IsActive, CreatedAt)
VALUES (1, 'admin', '<bcrypt_hash>', '', 'admin@bloodcenteros.com', 1, TRUE, NOW());

To generate a bcrypt_hash on the command line (requires Python):

pip install bcrypt && python -c "import bcrypt; print(bcrypt.hashpw(b'admin@123', bcrypt.gensalt(11)).decode())"

Or use any online BCrypt generator (cost factor 11).

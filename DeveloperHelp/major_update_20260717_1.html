BloodCenterOS v1.0

Major Update — 2026-07-17 (Build 1)

Subject: "Swagger gives 401 on all GET endpoints" — investigation, true root cause, and the fix.

Affected components: BloodCenterOS.API (JWT auth, Swagger), BloodCenterOS.Web (ApiClient → API calls).

1. The Reported Symptom

  • Opening Swagger UI and clicking Execute on any secured GET endpoint returned 401 Unauthorized.
  • Some endpoints returned 405 Method Not Allowed instead, which was confusing and looked inconsistent.
  • The Web application also failed to load data on protected pages.

2. What It Was NOT

Early diagnostics pointed at the JWT itself — a possible signing/validation secret mismatch. This was ruled out:

  • The JWT SecretKey, Issuer, and Audience are read from the same IConfiguration in both JwtService (sign) and Program.cs (validate).
  • We cryptographically verified the token signature against the configured key — it matched exactly.
  • The token was not expired (server UTC 06:33 < exp 14:33).

Conclusion: the token was always valid. The 401 was not a JWT problem.

3. The Two Real Root Causes

Cause A — A broken API build served a stale DLL

BloodCenterOS.API/Program.cs contained a Swagger configuration call:

c.IndexHtmlTransform((html) => { ... })

This method does not exist in Swashbuckle.AspNetCore 7.2.0, so the project failed to compile:

error CS1061: 'SwaggerUIOptions' does not contain a definition for 'IndexHtmlTransform'

Because subsequent runs used dotnet run --no-build, they executed a previously built (stale) DLL from before the route/auth fixes. That stale binary produced the erratic 401/405 behavior and made debugging impossible.

Cause B — HTTP→HTTPS redirect silently dropped the Bearer token

The API enforces app.UseHttpsRedirection(), so any call to http://localhost:5000 is redirected (307) to https://localhost:5001.

  • Test calls (and the Web app) targeted http://localhost:5000.
  • When the 307 redirect fired, the Authorization: Bearer <token> header (and the auth cookie) was not carried over to the redirected HTTPS request.
  • The API then saw an anonymous request on a [Authorize] endpoint → 401.

The 405s came from endpoints that do not require auth (e.g. /api/donors had no parameterless [HttpGet]), so the redirect/anonymous request surfaced as 405 instead of 401 — which is why the failures looked inconsistent.

Key insight: this same redirect also broke the Web application — its ApiClient called http://localhost:5000, so every server-side API call lost its token.

4. The Fixes Applied

Fix 1 — Restore a clean API build

Removed the invalid IndexHtmlTransform call from Program.cs and used the standard Swagger UI setup:

app.UseSwagger();
app.UseSwaggerUI(c =>
{
    c.SwaggerEndpoint("/swagger/v1/swagger.json", "BloodCenterOS API v1");
    c.DocumentTitle = "BloodCenterOS API";
    c.DisplayRequestDuration();
});

API now builds with 0 errors and runs the current code.

Fix 2 — Point the Web directly at the API's HTTPS endpoint

BloodCenterOS.Web/appsettings.json:

"Api": { "BaseUrl": "https://localhost:5001" }

BloodCenterOS.Web/Program.cs — register HttpClient against the HTTPS URL and accept the dev self-signed certificate:

builder.Services.AddHttpClient<ApiClient>(client =>
{
    var baseUrl = builder.Configuration["Api:BaseUrl"] ?? "https://localhost:5001";
    client.BaseAddress = new Uri(baseUrl);
    client.Timeout = TimeSpan.FromSeconds(30);
}).ConfigurePrimaryHttpMessageHandler(() => new HttpClientHandler
{
    // Dev only: accept the API's self-signed HTTPS dev certificate.
    ServerCertificateCustomValidationCallback = (_, _, _, _) => true
});

This eliminates the redirect entirely, so the Authorization header is never dropped.

Fix 3 — TIMESTAMPTZ / return-type mismatches (42804) on list SPs

Several fn_*_get_by_center functions declared CreatedAt TIMESTAMP while the underlying table columns are TIMESTAMPTZ (populated by NOW()). PostgreSQL raised 42804: structure of query does not match function result type → 500 on /api/devices, /api/fridges, /api/hospitals.

  • DB/fn_device_fridge.sql — changed CreatedAt TIMESTAMP → TIMESTAMPTZ in 4 functions (with DROP FUNCTION guards).
  • DB/fn_newsletter_sms_email.sql — same fix for SMS/Email template get functions.
  • DB/fn_hospital.sql — new source file (was missing from repo, only existed in the DB dump); recreated fn_hospital_get_by_center with TIMESTAMPTZ.

All three scripts were applied to the database.

Fix 4 — Missing parameterless list GET routes (405 / 404)

  • DonorController — added [HttpGet] list action (GET /api/donors, 405 → 200) + a GetCenterId() helper.
  • CampController — added [HttpGet] list action (GET /api/camps, 404 → 200).
  • DB/fn_camp.sql (new) — added fn_camp_get_by_center returning all camps for a center.
  • ICampRepository / CampRepository — added GetByCenterAsync; fixed StartTime/EndTime mapping (timestamptz → TimeSpan via .TimeOfDay).

6. How To Run / Use

Swagger UI: open https://localhost:5001/swagger (use HTTPS, not HTTP). Click Authorize and paste Bearer <token> obtained from POST /api/auth/login with admin / admin@123.

Web app: open https://localhost:7180, log in with admin / admin@123. It now reaches the API over HTTPS and all protected pages load data.

7. Remaining (non-blocking)

A few controllers (e.g. newsletters, camp-inventory, testings) have no parameterless [HttpGet] list route, so a bare GET /api/<name> returns 404 by design — the Web UI uses their specific endpoints. Optional future work: add list GETs for full Swagger coverage.

BloodCenterOS v1.0

Major Update — 2026-07-20 (Build 1)

Subject: CRUD verification & bug fixes for Master modules — Devices, Fridges, Designations, Employees, SMS Templates, Email Templates, Newsletter Subscribers.

Context: Following the Swagger 401 root-cause fix (see major_update_20260717_1.html), an end-to-end CRUD smoke test was run against the live API over HTTPS with a valid JWT. This surfaced a recurring class of PostgreSQL stored-procedure bugs that returned HTTP 500 on Create/Read.

1. Symptom

  • POST /api/devices → 500 on create.
  • POST /api/employees → 500 on create/update.
  • GET /api/newsletter → 500 on read.
  • Other modules (Fridges, Designations, SMS/Email Templates) worked, but several shared the same latent defect.

2. Root Cause — Two Related PostgreSQL Defects

Defect A — 42883: function does not exist (DATE vs timestamp)

Several fn_*_create / fn_*_update functions declared their date parameters as DATE:

fn_device_create(..., p_purchase_date DATE, p_warranty_end DATE)
fn_employee_create(..., p_join_date DATE, ...)

The .NET repositories pass .NET DateTime values (e.g. DateOnly.ToDateTime(TimeOnly.MinValue)), which Npgsql serializes as timestamp without time zone. PostgreSQL does not auto-coerce timestamp → date during function overload resolution, so no matching function was found:

SqlState: 42883
function fn_device_create(bigint, text, text, text, timestamp without time zone, timestamp without time zone) does not exist

Defect B — 42804: structure of query does not match function result type (TIMESTAMP vs TIMESTAMPTZ)

Several fn_*_get_* functions declared their audit/timestamp columns as TIMESTAMP (or SubscribedAt TIMESTAMP), while the underlying table columns are TIMESTAMPTZ (populated by NOW(), which returns timestamptz):

fn_newsletter_get_by_center(...) RETURNS TABLE(..., SubscribedAt TIMESTAMP, ...)
-- but NewsletterSubscription.SubscribedAt is timestamptz

This raised:

SqlState: 42804
structure of query does not match function result type

when Dapper executed SELECT * FROM fn_....

The earlier 2026-07-17 session already fixed the same pattern in device/fridge get functions, hospital, and newsletter/email/sms get functions — but the create/update DATE-param variant and the newsletter SubscribedAt variant were still outstanding. This session closed those gaps.

3. Fixes Applied

Fix 1 — DB/OLD/fn_device_fridge.sql

  • Changed fn_device_create / fn_device_update date params DATE → TIMESTAMP, casting to DATE on INSERT/UPDATE (p_purchase_date::DATE).
  • Added DROP FUNCTION IF EXISTS ... guards so the parameter-type change actually takes effect (CREATE OR REPLACE cannot alter a parameter type).
  • Confirmed the get_by_id / get_by_center return types already use TIMESTAMPTZ.

Fix 2 — DB/OLD/fn_branch_department_designation_employee.sql

  • Changed fn_employee_create / fn_employee_update p_join_date DATE → TIMESTAMP (cast to DATE on insert/update).
  • Added DROP FUNCTION IF EXISTS guards for both.
  • Verified employee get_by_id / get_by_center already return TIMESTAMPTZ correctly.

Fix 3 — DB/OLD/fn_newsletter_sms_email.sql

  • Changed fn_newsletter_get_by_center and fn_newsletter_get_by_id return column SubscribedAt TIMESTAMP → TIMESTAMPTZ.
  • Added DROP FUNCTION IF EXISTS guards.
  • SMS/Email template get functions already returned TIMESTAMPTZ (fixed previously).

All three SQL files were re-applied to the database (bloodcenter):

psql -h localhost -p 5432 -U postgres -d bloodcenter -f DB/OLD/fn_device_fridge.sql
psql -h localhost -p 5432 -U postgres -d bloodcenter -f DB/OLD/fn_branch_department_designation_employee.sql
psql -h localhost -p 5432 -U postgres -d bloodcenter -f DB/OLD/fn_newsletter_sms_email.sql

5. Notes

  • Testing gotcha: a stale dotnet API process holding port 5001 caused "Host failed to start / address already in use", making tests hit a dead API. Always stop prior dotnet processes before re-running.
  • Source file location: the fn_*.sql stored-procedure source files currently live under DB/OLD/ (moved there in a prior cleanup). The database has all fixes applied. Consider relocating them back to DB/ for cleaner source tracking.
  • Consistent convention going forward: date parameters passed from .NET should be declared TIMESTAMP in SPs (cast to DATE only when writing to a DATE column), and all audit/timestamp return columns should be TIMESTAMPTZ.

Bugs Fixed This Session

Bug 5: UserRepository.GetByUserNameAsync

Crash: (DateTime)result.createdat — column not in fn_user_get_by_username output (10 cols vs 14 mapped)

Why it wasn't caught: AuthService.LoginAsync does its own direct Dapper query against fn_user_get_by_username accessing only 6 fields — it never calls UserRepository.GetByUserNameAsync. There is no UserController, so this repo method is only callable internally. The bug was latent: if any future code called UserRepository.GetByUserNameAsync, it would crash on (DateTime)result.createdat.

Fix: Removed CreatedAt, CreatedBy, UpdatedAt, UpdatedBy (only 10 mapped now, matching SP).

Bug 6: ComponentRepository.GetAvailableAsync

Crash: (DateTime)r.createdat — column not in fn_component_get_available output (6 cols vs 10 mapped)

Why it wasn't caught: The integration tests passed because the test database has no blood components (0 rows). The rows.Select(...) lambda never executed. If a component existed in the DB, GET /api/components/available would return 500.

Fix: Removed CenterId, ParentBagId, CurrentStatus, CreatedAt — only map the 6 columns the SP returns.

Bug 7: IssueRepository.GetPendingRequestsAsync

Data loss: 7 phantom columns mapped (CenterId, HospitalId, PatientAge, PatientGender, PrescriptionAttachmentId, RequestedByUserId, RelatedIssueId) plus missed HospitalName which the SP does return.

Why it wasn't caught: Same zero-row scenario — no pending patient requests in the test DB. All phantom columns are nullable casts, so no crash, but silent data loss.

Fix: Map only the 8 SP columns: RequestId, PatientName, BloodGroup, ComponentType, UnitsRequested, RequestUrgency, RequestDate, HospitalName.

Recurring Pattern: Final Taxonomy

⚠ Root cause across all 7 bugs:
  1. SP body uses SELECT * instead of explicit column list — returns physical table order, not RETURNS TABLE order (Bugs 1)
  2. Ambiguous column references — RETURNS TABLE(campid) shadows BloodCampMaster.CampId in WHERE (Bug 1)
  3. C# code maps every model property — assumes the SP returns the full entity, but the SP often returns a subset (Bugs 2-7)
  4. Dapper dynamic + non-nullable cast — accessing a missing dynamic property returns null, which crashes on (DateTime)null or (long)null (Bugs 2-6)
  5. Zero-row test data hides bugs — rows.Select(...) with a 0-row result never executes, so phantom-column crashes only manifest when data exists (Bugs 6, 7)

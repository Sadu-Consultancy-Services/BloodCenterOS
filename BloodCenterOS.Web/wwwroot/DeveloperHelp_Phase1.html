BloodCenterOS — Phase 1 Developer Help

Blood Reception from MBB + Procurement Register

Overview

Phase 1 implements the inbound blood workflow: Blood Reception from Mother Blood Bank (MBB) and the Procurement Register — the central blood stock register.

Reference: BloodCenter24 forms Rcv_Blood.cs + Proc_Reg.cs.

Database Changes

Patch file: DB/patch_20260724_006_blood_reception.sql

New Tables

TablePurpose
BloodReceptionHeader for MBB receipt (MBB name, date, bill #, total bags)
BloodReceptionDetailLine items: donor info, bag #, bag type (SB/DB/TB/QB), expiry

Stored Procedures

SPPurpose
fn_blood_reception_createTransactional: creates header + details + donors + bags + components + inventory. Processes JSONB array of bag details. Bag type → component mapping: SB→WB, DB→PCV+FFP, TB/QB→PCV+FFP+PC
fn_blood_reception_get_by_idGet reception header by ID
fn_blood_reception_get_detailsGet detail line items for a reception
fn_blood_reception_get_by_centerList receptions with optional date filter
fn_procurement_register_searchSearch/filter all components (by blood group, component type, status, date range, keyword). Joins ComponentMaster → BloodBagMaster → DonorMaster
fn_procurement_register_summary8×4 matrix: blood groups × component types with Available/Reserved/Issued/Discarded counts

Lifecycle Statuses

Component CurrentStatus values:

  • Available — Ready for use
  • Reserved — Reserved for a patient
  • Issued — Issued to patient/storage
  • Discarded — Discarded (expired/quality)

Workflow

  1. User navigates to Blood Reception → clicks Receive Blood
  2. Enters MBB name, date, bill # (header)
  3. Adds rows for each bag (donor name, sex, blood group, contact, bag #, bag type, expiry, volume)
  4. Submit → SP transaction creates: DonorMaster + BloodBagMaster + ComponentMaster (× bag type components) + ComponentPreparation + InventoryStock updates
  5. All components set to Available status
  6. View in Procurement Register — filterable register with summary matrix

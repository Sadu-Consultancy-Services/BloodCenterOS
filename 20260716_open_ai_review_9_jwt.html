The Program.cs already has a safe-guard at line 21:

var jwtKey = builder.Configuration["Jwt:SecretKey"]
    ?? throw new InvalidOperationException("JWT SecretKey not configured");

This ensures the app fails fast at startup if the secret is missing, rather than producing invalid tokens at runtime.

Why This Matters

  • appsettings.json is typically committed to source control — the secret was previously visible to anyone with repo access
  • User Secrets are stored in %APPDATA%, per-developer, never committed
  • Tests use their own isolated key — a leaked test key doesn't compromise the real secret
  • Production secrets are managed via environment variables or Azure Key Vault, independent of both settings

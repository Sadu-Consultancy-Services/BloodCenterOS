Bugs Fixed

Bug 1: GET /api/donors/search — 500 Internal Server Error

Error: Cannot convert null to 'System.DateTime' because it is a non-nullable value type

Root Cause: fn_donor_search returns only 12 columns (donorid, centerid, donorcode, firstname, lastname, gender, phone, bloodgroup, city, lastdonationdate, totaldonations, totalcount), but DonorRepository.SearchAsync mapped 23 properties including Email, DateOfBirth, AadhaarNumber, AddressLine1, AddressLine2, Pincode, Occupation, PreferredLanguage, CreatedAt, CreatedBy, UpdatedAt, UpdatedBy — none of which exist in the SP output.

The crash hit CreatedAt = (DateTime)row.createdat (line 147, non-nullable DateTime). Accessing a missing dynamic property on ExpandoObject returns null, and casting null to non-nullable DateTime throws.

Fix — map only the 11 donor columns the SP actually returns:

// BEFORE — 23 properties, crashes on (DateTime)row.createdat
list.Add(new Donor {
    DonorId = (long)row.donorid,
    CenterId = (long?)row.centerid,
    ...
    CreatedAt = (DateTime)row.createdat,   // not in SP → CRASH
    CreatedBy = (long?)row.createdby,      // not in SP
    UpdatedAt = (DateTime?)row.updatedat,  // not in SP
    UpdatedBy = (long?)row.updatedby       // not in SP
});
// AFTER — only columns the SP returns
list.Add(new Donor {
    DonorId = (long)row.donorid,
    CenterId = (long?)row.centerid,
    DonorCode = (string?)row.donorcode,
    FirstName = (string)row.firstname,
    LastName = (string?)row.lastname,
    Gender = (string?)row.gender,
    BloodGroup = (string?)row.bloodgroup,
    Phone = (string?)row.phone,
    City = (string?)row.city,
    LastDonationDate = (DateTime?)row.lastdonationdate,
    TotalDonations = (int)row.totaldonations
});

Bug 2: POST /api/camps (integration test) — 500 Internal Server Error

Error: Unknown error (xUnit assertion: result.Message was null, indicating a 500 response)

Root Cause: The test sent startTime and endTime as ISO 8601 timestamp strings ("2026-12-25T08:00:00"), but fn_camp_create declares those parameters as interval type. Dapper transmits DateTime / string as timestamp without time zone, causing a PostgreSQL type mismatch.

These fields are nullable in both the model and the SP, so they can be omitted entirely.

Fix — remove startTime/endTime from the request body:

campDate = "2026-12-25T00:00:00",
startTime = "2026-12-25T08:00:00",   // ← SP expects interval, not timestamp
endTime = "2026-12-25T16:00:00",     // ← same issue
totalDonorsExpected = 100
campDate = "2026-12-25T00:00:00",
totalDonorsExpected = 100

Recurring Pattern — The Three Manifestations

⚠ Dapper dynamic + SP column mismatch — now observed in 4 locations

This session marks the third and fourth occurrence of the same bug class:

#File / ComponentSP Returns N columnsCode MapsCrash Point
1CampRepository.GetByIdAsync1114(int)r.totaldonorsexpected
2CampRepository.GetUpcomingAsync614(DateTime)r.createdat
3InventoryRepository.GetStockAsync510(long)r.inventorystockid
4DonorRepository.SearchAsync1223(DateTime)r.createdat

Lesson: Every SP's RETURNS TABLE column set must be explicitly checked against its corresponding C# mapping. Dapper dynamic access to non-existent properties returns null, which only crashes on non-nullable value types (DateTime, long, int). Nullable types (DateTime?, long?) silently succeed with null, masking the bug.
